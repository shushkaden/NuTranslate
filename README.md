# NuTranslate

Расширение для Chrome, которое делает две вещи.

1. **Переводит страницу по хоткею** (по умолчанию <kbd>Alt</kbd>+<kbd>T</kbd>) и тем же хоткеем возвращает оригинал, мгновенно и без перезагрузки. Перевод бережный: расширение меняет только текст внутри существующих узлов, поэтому формы и сайты на React и Vue продолжают работать, а оригинал восстанавливается байт в байт. Перед отправкой формы оригинал возвращается сам.
2. **Помогает встроенному переводчику Chrome** определять настоящий язык страницы, чтобы литовские сайты не переводились так, будто они написаны по-английски.

## Перевод по хоткею

Нажмите <kbd>Alt</kbd>+<kbd>T</kbd>, и страница переведётся на ваш язык. Ещё одно нажатие вернёт оригинал. То же самое делает большая кнопка в окне расширения. Сочетание клавиш меняется на странице `chrome://extensions/shortcuts`.

Как это устроено.

- **Структура страницы не меняется.** Встроенный переводчик Chrome оборачивает текст в теги `<font>`, и из-за этого React-приложения падают, а формы отправляют переведённые значения. NuTranslate не добавляет, не удаляет и не переставляет ни одного элемента. Он меняет только значения текстовых узлов и нескольких атрибутов (`placeholder`, `title`, `alt`, `aria-label`) и запоминает каждое изменение.
- **Данные форм не переводятся никогда.** Расширение не трогает содержимое `<textarea>`, значения полей и значения именованных кнопок отправки. Если у `<option>` нет атрибута `value`, браузер отправляет его текст, поэтому перед переводом NuTranslate закрепляет исходный текст в `value`, и форма отправляет то же, что и без перевода. Код (`<code>`, `<pre>`), элементы с `translate="no"` и `class="notranslate"` и редактируемые области тоже остаются как есть.
- **Перед отправкой формы оригинал возвращается сам.** Расширение ловит отправку раньше любого обработчика страницы, возвращает исходный текст и показывает короткое сообщение. Чтобы снова перевести страницу, нажмите хоткей. Это поведение выключается в настройках.
- **Язык оригинала берётся из собственного определения**, а не из `<html lang>`. Каждый достаточно длинный абзац проверяется отдельно, поэтому английский cookie-баннер на литовском сайте переводится с английского, а текст, который уже написан на вашем языке, вообще не отправляется.
- **Новый контент переводится сам.** Если сайт подгружает текст или перерисовывает его, расширение замечает это и переводит изменившиеся абзацы.
- **Сначала переводится то, что видно.** Абзацы на экране уходят в первом запросе, остальное догружается следом.
- **Режим перевода живёт во вкладке.** После хоткея следующие страницы в этой вкладке тоже переводятся сами, пока вы не выключите перевод хоткеем. В окне расширения можно включить "Всегда переводить страницы на языке ..." для языка текущей страницы, тогда такие страницы будут переводиться без хоткея в любой вкладке.

Значок на кнопке расширения показывает состояние вкладки. Фиолетовый "RU" значит, что страница переведена на русский.

### Движки перевода

Расширение не обращается к внутренним сервисам Google. Есть два официальных варианта, а выбирается он в настройках.

**Google Cloud Translation.** Это движок Google Translate через официальный API с вашим собственным ключом. Качество такое же, как у Google Переводчика. Google берёт плату за символы сверх ежемесячного бесплатного объёма. На момент написания первые 500 тысяч символов в месяц были бесплатными, а дальше около 20 долларов за миллион, но лучше проверьте [актуальные цены](https://cloud.google.com/translate/pricing). Сколько символов ушло за месяц, видно в настройках расширения. Повторяющийся текст (меню, футеры) кешируется и второй раз не отправляется.

Как получить ключ.

1. Откройте [консоль Google Cloud](https://console.cloud.google.com/), создайте проект и привяжите к нему платёжный аккаунт.
2. В разделе APIs & Services, Library найдите Cloud Translation API и включите его.
3. В разделе APIs & Services, Credentials нажмите Create credentials, затем API key. В настройках ключа ограничьте его одним Cloud Translation API.
4. Вставьте ключ в настройках NuTranslate и нажмите "Проверить ключ".

Ключ хранится только в этом браузере. Расширение закрывает своё хранилище от контент-скриптов, поэтому веб-страницы до ключа добраться не могут, а сам ключ уходит только на `translation.googleapis.com` в заголовке запроса.

**Офлайн-переводчик Chrome** (Translator API, Chrome 138 и новее на компьютере). Он бесплатный, и текст не покидает компьютер, но переводит заметно хуже Google. Для каждой пары языков Chrome один раз скачивает пакет, а скачивание разрешает только после клика, поэтому запускать его нужно кнопкой "Скачать" в настройках NuTranslate. Этот движок переводит каждый текстовый узел отдельно, потому что не гарантирует сохранность разметки.

В режиме "Автоматически" расширение берёт Google Cloud, если задан ключ, и офлайн-переводчик, если ключа нет.

## Помощь встроенному переводчику Chrome

### Почему встроенный перевод ошибается

Chrome определяет язык страницы один раз, сразу после того как браузер разобрал HTML. Он берёт язык, который страница объявила сама (атрибут `lang` у `<html>`, а если его нет, заголовок `Content-Language`), и сверяет его со своей моделью. Всё это видно в исходниках Chromium, в `components/translate` и `components/language_detection`.

Модель смотрит всего на 768 символов текста, то есть на первые 256, на 256 из середины и на последние 256, и оставляет самый уверенный ответ. Дальше Chrome поступает так.

- Если модель не уверена, Chrome верит объявленному языку.
- Если модель согласна с объявленным языком, всё хорошо.
- Если модель уверенно не согласна, Chrome верит ей только в одном случае, когда страница объявила английский, а модель видит один из 12 популярных языков (испанский, португальский, японский, русский, немецкий, китайский упрощённый и традиционный, арабский, индонезийский, французский, итальянский, тайский). Литовского в этом списке нет, поэтому в остальных случаях Chrome сдаётся и считает язык неизвестным (`und`).

Отсюда две типичные беды литовских сайтов.

1. Сайт на WordPress или другой CMS объявляет `lang="en"`, потому что так стоит по умолчанию, а текст на нём литовский. Если в выборку модели попали английские ссылки "Skip to content" или английский cookie-баннер, Chrome считает страницу английской и переводит её с английского, то есть почти ничего не меняет. Тогда приходится вручную выбирать литовский в меню перевода.
2. Даже сайт с правильным `lang="lt"` получает `und`, если в начале или в конце текста стоит английский cookie-баннер или футер. Тогда Chrome не предлагает перевод сам, и настройка "Всегда переводить с литовского" на таком сайте не срабатывает.

### Что делает NuTranslate

1. Когда HTML уже разобран, а Chrome ещё не посмотрел на страницу, расширение определяет язык основного текста. Оно анализирует абзацы и пропускает меню, шапки, футеры и cookie-баннеры, пока основного текста хватает для уверенного ответа. Если объявленный язык другой, NuTranslate заменяет `lang` у `<html>`, и Chrome читает уже исправленное значение.
2. Затем расширение проверяет те самые три окна по 256 символов, которые увидит модель Chrome. Если в них попадает текст на другом языке, NuTranslate на один кадр добавляет в начало и в конец страницы скрытый текст на настоящем языке страницы, а сразу после того как Chrome прочитал страницу, убирает его. Скрытый текст не виден, не занимает места и скрыт от экранных дикторов.
3. Значок на кнопке расширения показывает, что произошло. Зелёный "LT" значит, что NuTranslate исправил объявленный язык. Синий "LT" значит, что язык был указан верно и расширение только подсказало модели Chrome.

Если страницу переводит сам NuTranslate, расширение заодно ставит на неё метку `notranslate`, чтобы встроенный переводчик Chrome не начал переводить её второй раз. Поэтому, если вы пользуетесь автопереводом NuTranslate, выключите в Chrome "Всегда переводить" для тех же языков.

### Хоткей для встроенного перевода Chrome

Включать и выключать сам встроенный перевод Chrome расширение не может, потому что Chrome не даёт расширениям такого способа. Публичного API для перевода у расширений нет, есть только приватный `languageSettingsPrivate` для страниц настроек Chrome. Стандартного сочетания клавиш для перевода страницы в Chrome тоже нет. Атрибут ссылок `hreftranslate`, которым Google Поиск открывает страницы сразу переведёнными, Chrome учитывает только при переходе со страниц Google. Поэтому хоткей в NuTranslate управляет собственным переводом расширения.

## Установка

1. Скачайте репозиторий (Code, затем Download ZIP) и распакуйте его или склонируйте через git.
2. Откройте `chrome://extensions` и включите режим разработчика в правом верхнем углу.
3. Нажмите "Загрузить распакованное расширение" и выберите папку репозитория, в которой лежит `manifest.json`.
4. Откройте настройки расширения, выберите язык перевода и движок, а для Google Cloud вставьте ключ.
5. Перезагрузите открытые вкладки. На страницах, которые были открыты до установки, расширение не работает.

Расширению нужен доступ ко всем сайтам, потому что оно должно успеть прочитать страницу раньше Chrome и переводить её. В сеть оно обращается только к выбранному движку перевода.

## Настройки

Перевод.

- **Хоткей.** Показывает текущее сочетание и открывает страницу, где его можно поменять.
- **Переводить на.** По умолчанию язык браузера.
- **Движок перевода и ключ Google Cloud.** См. раздел про движки.
- **Офлайн-пакеты языков.** Скачивание пакета для офлайн-переводчика Chrome.
- **Всегда переводить страницы на этих языках.** Коды языков через запятую, например `lt, lv`.
- **Возвращать оригинал перед отправкой формы.** Включено по умолчанию.
- **Показывать короткие сообщения на странице.**

Встроенный переводчик Chrome.

- **Исправлять язык страницы.** Подмена `lang` перед тем, как Chrome его прочитает.
- **Помогать модели Chrome.** Скрытые подсказки на один кадр. Без них страница с английским cookie-баннером получает `und` вместо `lt`.
- **Писать решения в консоль страницы.**

**Сайты, на которых NuTranslate ничего не делает.** По одному домену в строке, поддомены тоже учитываются. На таких сайтах скрипт расширения вообще не запускается. Переключатель для текущего сайта есть и в окне расширения.

## Ограничения

- Текст внутри `<iframe>` не переводится, в том числе платёжные формы в фреймах, и это скорее плюс.
- Если переводчик переставляет слова вокруг ссылки, ссылка остаётся на своём месте, а слова раскладываются вокруг неё в порядке перевода. Изредка из-за этого фраза читается чуть менее гладко, чем у Google Переводчика, зато DOM не меняется.
- Сайты, которые сравнивают видимый текст кнопок в своём JavaScript, в переведённом виде могут вести себя иначе. Для таких случаев и есть хоткей и автоматический возврат оригинала перед отправкой формы.
- Автоперевод при загрузке страницы стартует после события `load`, чтобы не мешать сайтам на React и Vue, поэтому на долю секунды виден оригинал.
- Язык для встроенного переводчика Chrome определяется по тексту, который есть на странице в момент окончания разбора HTML, потому что именно тогда на неё смотрит Chrome. Переходы внутри SPA без перезагрузки этот механизм не исправляет, а собственный перевод NuTranslate их подхватывает.
- Скрытая подсказка для модели Chrome живёт один кадр. На сайтах, которые в этот момент гидрируют React-разметку всего документа, теоретически возможен лишний перерендер. Если сайт ведёт себя странно, выключите подсказки или добавьте сайт в исключения.
- Похожие языки (хорватский, боснийский и сербский, малайский и индонезийский, хинди и непальский) расширение никогда не исправляет друг на друга.
- Для файлов на диске (`file://`) нужно включить доступ к URL файлов в карточке расширения.

## Разработка

```sh
npm test                               # юнит-тесты, нужен только Node 18+
npm i -D playwright && npx playwright install chromium
npm run test:e2e                       # язык для встроенного переводчика: настоящий Chrome и его модель
npm run test:e2e:translate             # перевод по хоткею с подставным Cloud Translation API
```

Первый e2e-стенд запускает Chrome for Testing с расширением, скачивает в `test/.cache` модель определения языка из тестовых данных Chromium и читает решения Chrome из `chrome://translate-internals`. Второй поднимает локальный сервер, который изображает Cloud Translation API, переключает перевод так же, как это делает хоткей, и проверяет, что формы не тронуты, а после выключения перевода HTML страницы совпадает с исходным байт в байт. Офлайн-переводчик Chrome автотестами не покрыт, потому что для него нужно скачать языковой пакет с серверов Google. Обычный брендированный Chrome для тестов не подходит, потому что он больше не принимает флаг `--load-extension`.

### Устройство кода

- `src/content/core.js` содержит чистую логику определения языка, проверки окон выборки Chrome и расчёта подсказок.
- `src/content/dom.js` собирает текст страницы для определения языка, читает текст так же, как его читает Chrome, и управляет скрытыми подсказками.
- `src/content/markup.js` превращает абзац со ссылками в HTML с метками `<a i=N>` для переводчика и раскладывает перевод обратно по исходным текстовым узлам.
- `src/content/segments.js` делит страницу на такие абзацы и решает, что переводить нельзя.
- `src/content/translator.js` включает и выключает перевод, точно восстанавливает оригинал, следит за новым контентом и защищает формы.
- `src/content/ondevice.js` работает с офлайн-переводчиком Chrome.
- `src/content/main.js` связывает всё по времени и решает, когда переводить автоматически.
- `src/translate/cloud.js` обращается к Google Cloud Translation API.
- `src/background.js` регистрирует контент-скрипт, обрабатывает хоткей, помнит режим перевода вкладок, ходит в Google Cloud с кешем и рисует значок.
- `src/popup` и `src/options` отвечают за окно расширения и страницу настроек, тексты лежат в `_locales/en` и `_locales/ru`.
- `tools/make_icons.py` рисует иконки.
