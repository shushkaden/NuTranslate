# NuTranslate

Расширение для Chrome, которое помогает встроенному переводчику Chrome правильно определять язык страницы. Само расширение ничего не переводит. Оно исправляет язык, с которого Chrome начинает перевод, поэтому литовские сайты перестают переводиться так, будто они написаны по-английски.

## Почему встроенный перевод ошибается

Chrome определяет язык страницы один раз, сразу после того как браузер разобрал HTML. Он берёт язык, который страница объявила сама (атрибут `lang` у `<html>`, а если его нет, заголовок `Content-Language`), и сверяет его со своей моделью. Всё это видно в исходниках Chromium, в `components/translate` и `components/language_detection`.

Модель смотрит всего на 768 символов текста, то есть на первые 256, на 256 из середины и на последние 256, и оставляет самый уверенный ответ. Дальше Chrome поступает так.

- Если модель не уверена, Chrome верит объявленному языку.
- Если модель согласна с объявленным языком, всё хорошо.
- Если модель уверенно не согласна, Chrome верит ей только в одном случае, когда страница объявила английский, а модель видит один из 12 популярных языков (испанский, португальский, японский, русский, немецкий, китайский упрощённый и традиционный, арабский, индонезийский, французский, итальянский, тайский). Литовского в этом списке нет, поэтому в остальных случаях Chrome сдаётся и считает язык неизвестным (`und`).

Отсюда две типичные беды литовских сайтов.

1. Сайт на WordPress или другой CMS объявляет `lang="en"`, потому что так стоит по умолчанию, а текст на нём литовский. Если в выборку модели попали английские ссылки "Skip to content" или английский cookie-баннер, Chrome считает страницу английской и переводит её с английского, то есть почти ничего не меняет. Тогда приходится вручную выбирать литовский в меню перевода.
2. Даже сайт с правильным `lang="lt"` получает `und`, если в начале или в конце текста стоит английский cookie-баннер или футер. Тогда Chrome не предлагает перевод сам, и настройка "Всегда переводить с литовского" на таком сайте не срабатывает.

## Что делает NuTranslate

1. Когда HTML уже разобран, а Chrome ещё не посмотрел на страницу, расширение определяет язык основного текста. Оно анализирует абзацы и пропускает меню, шапки, футеры и cookie-баннеры, пока основного текста хватает для уверенного ответа. Если объявленный язык другой, NuTranslate заменяет `lang` у `<html>`, и Chrome читает уже исправленное значение.
2. Затем расширение проверяет те самые три окна по 256 символов, которые увидит модель Chrome. Если в них попадает текст на другом языке, NuTranslate на один кадр добавляет в начало и в конец страницы скрытый текст на настоящем языке страницы, а сразу после того как Chrome прочитал страницу, убирает его. Скрытый текст не виден, не занимает места и скрыт от экранных дикторов.
3. Значок на кнопке расширения показывает, что произошло на текущей вкладке. Зелёный "LT" значит, что NuTranslate исправил объявленный язык. Синий "LT" значит, что язык был указан верно и расширение только подсказало модели Chrome. По клику открывается окно с подробностями и переключателем для текущего сайта.

После этого встроенный переводчик показывает правильный исходный язык, а в его меню можно включить автоматический перевод с литовского, и Chrome будет переводить такие сайты сам.

## Результаты проверки

Сценарии из `test/e2e/pages.js` в Chrome for Testing 153 с настоящей моделью определения языка. В колонках указан язык, который Chrome принял для страницы (его видно в `chrome://translate-internals`).

| Страница | Без NuTranslate | С NuTranslate |
| --- | --- | --- |
| Литовский текст, `lang="en"` | `und` | `lt` |
| То же плюс английские "Skip to content", cookie-баннер и футер | `en` | `lt` |
| Правильный `lang="lt"`, но английский cookie-баннер и футер | `und` | `lt` |
| Литовский текст без `lang` и с заголовком `Content-Language: en` | `und` | `lt` |
| Скрипт страницы сам возвращает `lang="en"` после загрузки | `und` | `lt` |
| Латышский текст с `lang="lt"` | `und` | `lv` |
| SPA, у которого при загрузке пустой `<body>`, но литовские title и description | `en` | `lt` |
| `lang="lt"`, а в середину выборки попала английская цитата | `und` | `lt` |
| Русский текст с `lang="en"` (Chrome справляется сам) | `ru` | `ru` |
| Английская статья с `lang="en"` | `en` | `en` |
| Половина текста литовская, половина английская (расширение не вмешивается) | `und` | `und` |

На странице примерно в 70 тысяч символов определение языка заняло около 20 мс, а проверка выборки Chrome около 8 мс.

## Установка

1. Скачайте репозиторий (Code, затем Download ZIP) и распакуйте его или склонируйте через git.
2. Откройте `chrome://extensions` и включите режим разработчика в правом верхнем углу.
3. Нажмите "Загрузить распакованное расширение" и выберите папку репозитория, в которой лежит `manifest.json`.
4. Перезагрузите открытые вкладки. На страницах, которые были открыты до установки, расширение не работает.

Расширению нужен доступ ко всем сайтам, потому что оно должно успеть прочитать страницу раньше Chrome. Оно ничего не отправляет в сеть и ничего не хранит, кроме своих настроек.

## Хоткей для встроенного перевода

Его в расширении нет, потому что Chrome не даёт расширениям никакого способа включить или выключить встроенный перевод.

- Публичного API для перевода у расширений нет. Есть только приватный `languageSettingsPrivate`, который доступен страницам настроек Chrome, но не обычным расширениям.
- Стандартного сочетания клавиш для перевода страницы в Chrome тоже нет, в таблице горячих клавиш Chromium для команды перевода ничего не назначено.
- Атрибут ссылок `hreftranslate`, которым Google Поиск открывает страницы сразу переведёнными, Chrome учитывает только при переходе со страниц Google.

Поэтому хоткей возможен только для собственного перевода внутри расширения, например через тот же движок Google Translate или через встроенный в Chrome офлайн-переводчик (Translator API, Chrome 138 и новее). Это отдельный режим перевода, а не встроенный инструмент.

## Настройки

- **Исправлять язык страницы.** Главный выключатель.
- **Помогать модели Chrome.** Включает скрытые подсказки из второго шага. Без них страница с английским cookie-баннером получает `und` вместо `lt`.
- **Писать решения в консоль страницы.** Пригодится, если на каком-то сайте язык определяется неверно.
- **Сайты, на которых NuTranslate ничего не делает.** По одному домену в строке, поддомены тоже учитываются. На таких сайтах скрипт расширения вообще не запускается. Переключатель для текущего сайта есть и в окне расширения.

## Ограничения

- Язык определяется по тексту, который есть на странице в момент окончания разбора HTML, потому что именно тогда на неё смотрит Chrome. Если сайт рисует содержимое скриптом позже, расширение берёт язык из `<title>` и описания страницы, а если их не хватает, ничего не меняет.
- Chrome определяет язык один раз за загрузку страницы, поэтому переходы внутри SPA без перезагрузки не исправляет ни Chrome, ни расширение.
- Скрытая подсказка живёт один кадр. На сайтах, которые в этот момент гидрируют React-разметку всего документа, теоретически возможен лишний перерендер. Если сайт ведёт себя странно, выключите подсказки или добавьте сайт в исключения.
- Если текста на странице больше 65 535 символов, Chrome обрезает его, и подсказку в конце страницы он уже не увидит. На практике в таких случаях конец выборки и так приходится на основной текст.
- Похожие языки (хорватский, боснийский и сербский, малайский и индонезийский, хинди и непальский) расширение никогда не исправляет друг на друга.
- Для файлов на диске (`file://`) нужно включить доступ к URL файлов в карточке расширения.

## Разработка

```sh
npm test                               # юнит-тесты логики, нужен только Node 18+
npm i -D playwright && npx playwright install chromium
npm run test:e2e                       # настоящий Chrome, сравнение без расширения и с ним
```

E2E-тест запускает Chrome for Testing с расширением, скачивает в `test/.cache` модель определения языка из тестовых данных Chromium и читает решения Chrome из `chrome://translate-internals`. Обычный брендированный Chrome не подходит, потому что он больше не принимает флаг `--load-extension`.

### Устройство кода

- `src/content/core.js` содержит чистую логику без DOM, то есть определение языка по кускам текста, проверку окон выборки Chrome и расчёт подсказок.
- `src/content/dom.js` собирает текст страницы, читает текст так же, как его читает Chrome, и управляет скрытыми подсказками.
- `src/content/main.js` связывает всё по времени. Обработчик `DOMContentLoaded` исправляет `lang`, а первый `requestAnimationFrame` проверяет выборку прямо перед тем, как Chrome на неё посмотрит.
- `src/background.js` регистрирует контент-скрипт с учётом исключений и рисует значок.
- `src/popup` и `src/options` отвечают за окно расширения и страницу настроек, тексты лежат в `_locales/en` и `_locales/ru`.
- `tools/make_icons.py` рисует иконки.
